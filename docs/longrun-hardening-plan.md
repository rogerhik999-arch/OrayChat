# 长跑加固实施计划（longrun-hardening）

> 依据：docs/longrun-sync-research.md（调研）+ 已落地的 P0 三件套
> （看门狗/增量游标同步/QoS1 会话保持，含 filex 重建循环有界化）。
> 本计划覆盖研究路线剩余项，按性价比排序执行。

## 任务清单

### A. 健康面板（可观测性，一切后续工作的地基）—— P3 提前
- [ ] relay 增加入站帧计数器 `framesIn`（看门狗已有 lastInboundAt，补速率面）
- [ ] 渲染层采样器（每 10min）：JS 堆内存（performance.memory）、blob URL 数、
      DOM 节点数、入站帧速率、链路断线总数、看门狗复位计数、就绪会话数
- [ ] 样本落 local-state `oc-health`（环形 144 条 = 24h）
- [ ] 设置页「健康」区块：当前状态行 + 最近样本列表
- 验收：面板显示真实数字；样本身随时间推进；单测覆盖采样函数

### B. 同步分块 + 节流（控制面/数据面隔离落地）—— 补齐 P0-② 边界
- [ ] pushSync 序列化后 >32KB 拆多帧（按条目字节预算分批，dels/clearT 随首批，
      names 随首批），帧间 50ms pacing
- [ ] 接收端零改动（applyState 幂等合并，逐帧生效）；txid 去重天然去重
- 验收：大增量拆多帧且接收端收敛一致（单测）；常规小帧不拆

### C. Lifeguard 化怀疑参数（假阳性翻动根治）—— P1
- [ ] SUSPECT_MS 20s → 按对端到达节奏动态（σ 大的链路宽限放大，≤60s）
- [ ] 本机链路劣化感知：近 10min 链路断开 ≥3 次 → 全部宽限窗 ×2（低敏感模式），
      恢复后自动回常态；GHOST_MAX_LIFETIME_MS 90s 硬上限保留（双保险纪律）
- 验收：单测覆盖动态宽限与劣化模式；回收器既有测试不回归

### D. presence 智能降频（流量减半）—— P2
- [ ] 成员集合稳定 5min（无进出/无新 presence 认知变化）→ 广播 10s→30s；
      任何变化立即回 10s
- [ ] 接收端无需改（adaptiveTtl 按到达节奏自适应，天然跟随）
- 验收：单测覆盖升降频切换；e2e 在线状态不回归

### E. 72h 双实例 soak 台架（长跑的最终验证）
- [ ] test/soak-longrun.mjs：双实例同房 + 每 5min 采样（READY 双向、日志异常、
      掉线次数）→ 报告落 /tmp/oc-soak-report.jsonl
- [ ] 每 2h 自动重启一个实例（模拟设备重启）；进程崩溃如实记录不自动复活
- [ ] nohup 启动，用户可随时查报告；结论以"72h 内无人工干预掉线"为准
- 验收：台架启动成功且持续产出样本（结论待真实时间轴）

## 执行顺序
A → B → C → D → 回归（单测 + comprehensive）→ E 启动 → 提交 main。

## 不做（本轮明确排除）
- Merkle 分桶对账（等"换设备/清数据首连成本"成为真实痛点）
- sync 搬 Web Worker（渲染卡顿无实测证据）
- Trystero 信令自愈（次生风险，观测中）
- hub 离线队列上限（小改，随下次中继迭代）
