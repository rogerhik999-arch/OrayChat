# 分布式通讯的网络健壮性方法 —— 调研与本项目应用路线

> 状态：调研完成（2026-09-29）。已实现项标注版本号；未实现项按性价比排序，
> 供后续迭代选用。参考实现：SWIM/Consul/Serf（成员管理）、Nostr（多中继）、
> ZeroTier/Tailscale（NAT 保活）、RFC 7675（ICE consent）、Epidemic Protocols（反熵）。

## 一、问题域拆解

健壮性 = 四个子问题的乘积，任何一处短板都会表现为"掉线/看不到人/丢消息"：

1. **成员管理**（谁在线？）—— 故障检测与成员表收敛
2. **数据面可靠性**（消息必达？）—— ACK/重传/去重/离线补投
3. **路径多样性**（路断了有得换？）—— 多通道并联与快速切换
4. **会话恢复**（断了能快续？）—— 保活、断点续传、密钥复用

## 三、建议实施项（按性价比排序）

### P0-1 多 broker 并联订阅（Nostr 式）✅ v1.11.0 已落地
**痛点对应**：整个测试期间最大的环境问题就是公共 broker 抖动（SSL 断连、订阅延迟、
截断）。当前实现单 broker 在连，故障→切换→重订阅有 5-10s 窗口，切换期间
presence/握手帧全丢。
**方案**：同时维持 2-3 条 broker 连接（各自订阅同一批 topic），发送时随机挑一条，
接收按 `from+mid/txid` 去重。任一 broker 挂掉零感知；三条同时挂才降级重连。
**工作量**：relay.mjs 改造约半天；digest/握手帧天然幂等，去重成本低。

### P0-2 周期性反熵（全量对账）✅ v1.11.0 已落地
**痛点对应**：删除传播依赖 ctl 帧单发；长在线不重连的两端，日志可能长期不一致；
离线消息也依赖下次握手的 pushSync。
**方案**：每 5 分钟向一个随机就绪对端 pushSync 全量状态（反熵轮）。CRDT 合并语义
已有，纯增量改动。
**工作量**：约 1 小时。gossip 理论保证 O(log n) 轮收敛。

### P1-3 SWIM 完整化（suspicion + ping/digest 复活）✅ v1.11.0 已落地（ping-req 用 digest 复活等价实现）
**痛点对应**：固定 30s TTL 在网络慢时把"活着但延迟"的成员判死（界面闪烁"离线"），
又把真死的成员拖满 30s 才消失。
**方案**：TTL 到期先标 `suspect`（界面显示"疑似离线"），摘要在 gossip 中传播怀疑；
本地或经任一共同好友（ping-req）探测确认后才 `dead`。误判率与检测延迟双降。
**工作量**：1 天左右（digest 已带成员表，扩展字段即可）。

### P1-4 消息级 ACK 与重传 ✅ v1.11.0 已落地
**痛点对应**：中继路径 QoS0 丢消息无感知（聊天表现为"对方没回"，实际是没收到）。
**方案**：信封已有 mid；接收端回 `ack{mid}`，发送端 3s 未收 ACK 重发（最多 3 次），
接收端按 mid 去重。仅对 dm/lobby 消息帧做（握手帧已有重传）。
**工作量**：1 天。注意与 30 天日志的 mid 幂等配合，去重天然成立。

### P2-5 定时器抖动 + 自适应 TTL ✅ v1.12.0 已落地
presence 10s→10±2s 随机；TTL 按 RTT 方差自适应（简化版 φ-accrual）。
工作量：2 小时。防雷群、降误判。

### P2-6 make-before-break 路径迁移 ✅ v1.12.0 已落地（就绪会话切换后旧路径 10s 宽限接收，同钥双路+序号去重）
p2p↔中继切换时并行跑两条路直到新路确认就绪再拆旧路。消除迁移窗口丢帧。
工作量：半天（与 via 锁定机制协同设计）。

### P3-7 会话恢复（epoch 密钥复用）✅ v1.12.0 已落地（默认开启，设置页可关；票据仅存内存）
断线重连时用上次会话密钥派生新 epoch 快速续接（跳过 4 帧握手）。
**权衡**：牺牲少量前向保密（密钥延续），换取重连速度。可做成默认关闭的选项。
工作量：1-2 天，需谨慎评审安全模型。

### P3-8 残身回收（ghost reaping）✅ v1.14.0 已落地
peerId（Trystero selfId）每次启动随机生成：对端重启/换网即以新 peerId 回来，
旧条目若死亡路径未触发（崩溃时 WebRTC 无 leave 事件、p2p 会话不走 onRelayGone）
会永远挂在在线列表。三重治理：
- **身份去重**：握手学到 idPubHex 即确认"新旧条目是同一人"，立即清理旧 peerId 条目
  （对端重启场景秒清）；同名（昵称即账号）且非 ready 且中继视野无 presence 的旧条目一并接管。
- **周期回收**（15s）：两条可靠证据链同时成立才判死 —— 中继视野（我方 relay 稳定
  ≥75s 预热）里已无 presence，且直连通道不是 connected。ready 会话自怀疑起点再留
  90s 宽限（ping/digest 复活窗口）；failed/handshaking 自最后进展 90s。清掉的条目
  自动落入"历史联系人"（按身份公钥组织，不丢聊天记录）。
- **防复种**：刚回收的 peerId 进 5 分钟冷却名单，digest 摘要不得据此重建条目；
  间接介绍每 peerId 上限 2 次，会话建立后清零。
- **旧身份归并**（v1.15.0）：重装/清数据换密钥后，同昵称（昵称即账号）的旧公钥经
  读时合并归入当前身份 —— 名录不再多列、聊天记录合并成一条时间线；别名只在
  E2EE 握手就绪（名字受签名保护）时建立，原始分桶不动、清 `oc-id-aliases` 即还原。

## 四、已被验证"不需要"的方向

- **DHT/无中心发现**：房间人数 ≤ 数百，presence 广播 + gossip 已够；DHT 引入的
  复杂度与延迟不成比例。
- **自建 TURN/信令服务器**：当前 MQTT 中继 + E2EE 已覆盖；私有化部署文档里保留
  自托管 broker/coturn 路径即可。
- **消息持久化队列服务**：共享日志（全体保存 + 上线同步）已是去中心化等价物。
